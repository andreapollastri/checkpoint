Overview

Checkpoint is a Laravel security scanner. It runs a fixed set of built-in checks (plus optional custom ones) and prints a PASS / WARN / FAIL report. Use it locally, after Composer installs, or as a pipeline gate.

It is a static / config / process auditor — not a runtime WAF and not a full SAST engine. Pair it with containers and install-time guards for supply-chain defense in depth.

Requirements

  • PHP ^8.1 (your Laravel major may require higher)
  • Laravel 8–13 (illuminate/support + illuminate/console)

Installation

bash 
composer require --dev andreapollastri/checkpoint

Package discovery registers the service provider automatically. Publish config only when you need toggles, suppressions, or custom checks:

bash 
php artisan vendor:publish --tag=checkpoint-config

Usage

Run every check

bash 
php artisan checkpoint:scan

Limit or skip checks

Flags match check display names (case-insensitive), comma-separated.

bash 
php artisan checkpoint:scan --only="SQL Injection Risks,CSRF Protection"
bash 
php artisan checkpoint:scan --skip="NPM CVE Audit,Debug Functions in Production Code"

JSON for CI

bash 
php artisan checkpoint:scan --json | tee checkpoint-report.json

Each finding includes a stable 12-character hash for suppressions. In CI scripts that pipe through tee, enable pipefail so the Artisan exit code is preserved.

Fail on warnings

By default WARN does not fail the process. For stricter gates:

bash 
php artisan checkpoint:scan --fail-on-warn

Configuration

Published file: config/checkpoint.php. Checks omitted from the map default to enabled, so upgrades keep new protections without re-publishing.

Toggle checks

php — config/checkpoint.php
'checks' => [
    Checks\ComposerAuditCheck::class => true,
    Checks\NpmAuditCheck::class      => false, // PHP-only apps
    // …
],

Custom checks

php — config/checkpoint.php
'extra_checks' => [
    \App\Security\MyCustomCheck::class,
],

Classes may take no constructor args, or a single $basePath string. Disable an extra check with the same checks map.

Package freshness

php — config/checkpoint.php
'package_freshness' => [
    'minimum_age_days' => 3,
    'whitelist' => [
        'andreapollastri/checkpoint',
        // 'vendor/package',
    ],
],

Set minimum_age_days to 0 to bypass the age gate without removing the check.

Suppress findings

Every WARN/FAIL detail shows a hash like [a1b2c3d4e5f6]. Copy it into config:

php — config/checkpoint.php
'suppressed' => [
    'a1b2c3d4e5f6',
],
Hashes ignore line-number shifts. Changing the file path or finding text invalidates the hash on purpose. If every finding for a check is suppressed, the check becomes PASS with an explicit suppression message.

Exclude paths

php — config/checkpoint.php
'exclude_paths' => [
    'storage/app/mounted-data',
    'data/external',
],

Merged on top of built-in skips (vendor/, node_modules/, storage/, …). Paths are relative to the project root.

Suspicious autoload whitelist

Under suspicious_autoload.whitelist, add package names or vendor/* wildcards for trusted autoload.files entries beyond the baked-in list.

Custom checks

Extend AbstractCheck and return a CheckResult:

php
use Checkpoint\Checks\AbstractCheck;
use Checkpoint\Checks\CheckResult;

class MyCustomCheck extends AbstractCheck
{
    public function name(): string
    {
        return 'My Custom Check';
    }

    public function run(): CheckResult
    {
        return CheckResult::pass('Everything looks good.');
        // CheckResult::warn('Review this.', ['detail']);
        // CheckResult::fail('Critical.', ['detail']);
    }
}

Register the class in extra_checks so php artisan checkpoint:scan includes it. You can also build a Scanner manually with Scanner::withDefaultChecks($path)->add(...).

CI / CD

GitHub Actions

bash 
php artisan checkpoint:github

Writes .github/workflows/checkpoint.yml: push to main/master and all PRs, PHP 8.2, Composer cache, optional Node + npm ci when package-lock.json exists, checkpoint:scan --json with report artifact. Use --force to overwrite.

GitLab CI

bash 
php artisan checkpoint:gitlab

Creates .gitlab-ci.yml (or prints a snippet if one already exists). Same idea: JSON report artifact, optional Node on Alpine when a lockfile is present. --force overwrites.

Composer hooks

bash 
php artisan checkpoint:install-hooks

Appends @php artisan checkpoint:scan to post-install-cmd and post-update-cmd. Idempotent; --remove uninstalls; --force replaces stale entries.

Only post-* hooks: pre-update-cmd runs before resolution (useless against a package about to land), and pre-install-cmd on a fresh clone has no vendor/ yet so Artisan cannot run. Real-time install interception belongs to Docker and Safe-Chain — see Companion tools.

Exit codes

Code Meaning
0 All checks passed, or only warnings (unless --fail-on-warn)
1 At least one FAIL, or a WARN when --fail-on-warn is set

Companion tools

Checkpoint inspects the tree; it does not intercept package installs. Harden the install path separately.

Docker (recommended)

Run composer install, npm install, and the scan inside a container. Malicious post-install scripts stay off your host keys and browser profile.

bash 
docker compose exec app php artisan checkpoint:scan

Safe-Chain

Safe-Chain blocks known-malicious npm packages before install scripts run. Checkpoint’s Supply Chain Tooling check warns when neither Safe-Chain nor Socket CLI is on PATH and package.json exists.

bash 
npm install -g @aikidosec/safe-chain
safe-chain setup

Limitations

  • Many app-level checks are regex / heuristics. Expect false positives and false negatives around indirection, bindings, or multi-line constructs.
  • Environment checks read the runtime config of the process running Artisan — not necessarily production .env.
  • NPM audit needs Node and a lockfile on the machine that runs the scan.
  • Package freshness can fail legitimate urgent security patches until you whitelist or lower the window.
